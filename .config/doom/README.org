#+title: Notes and journal
#+startup: overview

An org-mode mirror of my Obsidian vault (=Cortex=). Same shape, same schema,
different tool — the two run side by side and neither converts the other.

There is no bullet journal here: no migration ritual, no signifiers, no habit
tracker, no collections. A day is a page you write on. A note is a note.

* Layout
| ~journal/~     | One file per day, =YYYY-MM-DD.org=. Flat.              |
| ~notes/~       | The knowledge base — atomic, MoC, people. Flat.        |
| ~archive/~     | Archived subtrees, datetree'd, one file per source.    |
| ~calendar.org~ | Written by org-gcal. Don't hand-edit.                  |

Mirrors =Cortex/Journal/Daily/= and =Cortex/Notes/= respectively. Note filenames
are sentence case with spaces, as in the vault: =Kubernetes pod.org=.

* Schema
The vault's YAML frontmatter becomes file-level org properties, which is what
org-roam indexes into its DB — =#+keywords= are not indexed.

| Vault YAML              | Here                                 |
|-------------------------+--------------------------------------|
| =type: atomic=          | =:TYPE: atomic=                      |
| =topic: "[[Kubernetes]]"= | =:TOPIC:= holding an org-roam link |
| =status: seedling=      | =:STATUS: seedling= → =evergreen=    |
| =created: 2026-06-15=   | =:CREATED:=                          |
| =tags: [topic/devops]=  | =#+filetags: :topic_devops:=         |
| =category:= (person)    | =:ROLE:=                             |

Two deliberate differences. Org tags cannot contain a slash, so the
=topic/domain/subdomain= taxonomy is written =topic_domain_subdomain=. And a
person's =category= is =:ROLE:=, because org reserves =:CATEGORY:= for the agenda;
same values as the vault — scientist / visionary / economist / author / engineer
/ photographer.

* Backlinks are the query engine
The vault leans on dataview: a MoC lists its children with
=WHERE contains(topic, [[X]])=, and a daily lists the notes written that day.
There is no dataview in org and none is needed for the first case.

Put an org-roam link in a note's =:TOPIC:= property (=SPC n r i= inside the
drawer) and that note *is* a backlink of its parent. =SPC n r b= on the parent
lists every child, live, with nothing to maintain. That is the MoC landscape.

The same mechanism connects the journal to the wiki: link =[[Kubernetes pod]]= in
a day's log and the log shows up in that note's backlinks.

* Note types
=SPC n r n= then pick:

| =a= | atomic         | the default — one self-contained idea              |
| =m= | map of content | pure navigation, only when no hub note fits        |
| =p= | person         | role, nationality, born, contributions             |

Prefer a *hub atomic note* — a real note that happens to have many children
pointing at it — over a MoC. A MoC is for a domain with no natural centre.

Templates live in =$DOOMDIR/templates/= and are read fresh on every capture, so
editing one takes effect on the next note, no restart.

* The day
=SPC X= opens the capture window; =t= is a task, =n= a note. Both land under
=* Notes= in today's file. Tasks are ordinary =TODO= headings written where they
occurred — give one a =SCHEDULED:= or =DEADLINE:= stamp and it shows on the
agenda, otherwise it stays where you left it.

| =SPC n j j= | today       | =SPC n j p= | previous log written |
| =SPC n j y= | yesterday   | =SPC n j n= | next log written     |
| =SPC n j t= | tomorrow    | =SPC n j w= | this week            |
| =SPC n j d= | pick a date | =SPC n j W= | last week            |
| =SPC n j b= | browse      |             |                      |

* The week
There is no weekly file. =SPC n j w= generates one: a scratch buffer holding the
week's days, each day's =* Notes= pulled in live by org-transclusion. Nothing is
written to disk, so nothing goes stale and there are no seven links to maintain
by hand. Close it and it's gone.

The vault's weekly note earned its keep because dataview filled it in. Without a
query engine, a weekly file is just chores.

* Agenda
=SPC o a a= is the week, =SPC o a t= the open tasks — Doom's own bindings, no
custom views. Scope is the last 90 days of the journal plus =calendar.org=; a
task you haven't touched in three months is a diary line, not a task.

=SPC o a c= opens the calfw month view.

* Google Calendar
=SPC n g s= syncs both ways. Inert until credentials are in the macOS Keychain;
see the org-gcal section of =$DOOMDIR/config.el= for the one-time setup.
